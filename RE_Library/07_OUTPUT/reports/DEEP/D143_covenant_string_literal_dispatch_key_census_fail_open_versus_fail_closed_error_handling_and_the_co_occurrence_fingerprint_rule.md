# D143 — Covenant string-literal dispatch: the complete key census, fail-open vs fail-closed error handling, and a co-occurrence rule with a measured false-positive count

**SCOPE:** `RE_Library\01_SOURCE_c2\covenant` — 979 files enumerated; **254 source files analysed** (152 `.cs` + 102 `.razor`), excluding 620 `wwwroot` vendored assets and 9 `refs`. Static read only.
**DEFINER SCOPE:** Every dispatch key below is defined by a `case "…":` arm or a `[EnumMember(Value = "…")]` attribute *in the file and line cited*. No key is inferred from a variable, method, or type name.
**CONDITIONAL SCOPE:** The fail-open/fail-closed verdicts hold **for the 8 `default:` arms enumerated at §3** and **for the 22-file API model family at §4**. They are NOT generalised to the grunt runtime paths in `GruntHTTP.cs` / `GruntSMB.cs` / `GruntBridge.cs`, which were not exhaustively read. The co-occurrence rule at §6 is validated **against 6 in-corpus trees, not against the world**.
**COUNTED:** 254 source files → **154 string-literal `case` arms** in **26 files**, **119 distinct key values**; **8 `default:` arms tree-wide**; **44 `return null;` sites in `API\Models`** across 22 files. Comparator for every count stated inline.

## 0. Method corrections carried into this report

Three defects from the prior round are corrected here rather than repeated. They are stated first because each changes a number below.

**(a) The glob-coverage defect.** My D133 scope was `*.cs`, which silently excluded 102 `.razor` files — the source of 3 false "absence" findings. **This report's definer scope was proven before any search ran:** 979 files enumerated, grouped by extension, `wwwroot` (620) and `refs` (9) quantified as vendor and excluded, leaving 254. The `.razor` files are in scope and they matter: **23 of the 154 arms (14.9%) live in `.razor` files** and would have been missed by the old scope.

**(b) The instrument-shape defect.** My D133 `using`-directive detector returned 7-of-21 "DEAD" verdicts that were live, because DI extension methods never appear in a `using`. The lesson generalises to this report: **a dispatch key must be read from a `case` arm or an `[EnumMember]` attribute, never from a symbol reference.** Every key below is a literal.

**(c) The comparison defect.** The Lead's `verify N` invocation took no argument and printed identical output for two different inputs, which was misread as agreement. **Identical output from two different inputs is evidence the input never reached the function.** Applied here: the Covenant/havoc ratio at §3 is computed from two *independently enumerated* counts of the same feature, and is reported per-side so both can be re-run.

**`ldstr` survival.** A `case "…"` arm compiles to a string-literal comparison; the literal is emitted as an `ldstr` operand in the IL. IL string literals are interned into the metadata **`#US` heap** and **cannot be constant-folded away by the C# compiler** — the comparison has to happen at runtime. ## 3. Fail-open vs fail-closed — Covenant is the **opposite** of havoc, and the contrast is measured

The Lead's question: havoc's numeric dispatch **fails closed** (`Packager.cc:785` → `"[PACKAGE] Command not found"`) while string dispatch **fails open**. Is Covenant the same?

**Both sides measured with the same instrument** (extension-filtered `case "` and `default:` census):

| | Covenant | havoc |
|---|---:|---:|
| source files in scope | **254** (`.cs`+`.razor`) | **333** (`.cpp`/`.cc`/`.h`/`.hpp`/`.cs`/`.go`/`.py`) |
| string-literal `case` arms | **154** | **134** |
| `default:` arms | **8** | **175** |

**Comparator: same regexes (`\bcase\s+"`, `^\s*default\s*:`), extension sets stated per tree. Havoc's count includes C++ `default:` in `switch` statements, which is the same construct.** The ratio is **8 : 175**, a 22:1 divergence, and it holds because Covenant's generated enum family has *no* `default:` at all — see §4.

**havoc, verified at the cited site — `Packager.cc:785-787`:**
```
L785  default:
L786      spdlog::error( "[PACKAGE] Command not found" );
L787      break;
```
and `Packager.cc:215-216`: `default: return false;`. **Loud, and rejecting.**

**Covenant's eight `default:` arms, all of them, with behaviour:**

| # | site | default arm does |
|---:|---|---|
| 1 | `CovenantService.cs:1643` | `return CodeTemplate;` — returns the **unmodified** template, silently |
| 2 | `CovenantService.cs:3214` | falls through to a **broader** `FirstOrDefaultAsync` query — loosens the match |
| 3 | `Utilities.cs:147` | `return ".cs";` — an unmatched language silently becomes C# |
| 4 | `Brute.cs:996` | `sb.Append(c);` — passes the character through |
| 5 | `GruntBridge.cs:1150` | `sb.Append(c);` |
| 6 | `GruntHTTP.cs:1299` | `sb.Append(c);` |
| 7 | `GruntSMB.cs:1175` | `sb.Append(c);` |
| 8 | `InternalListener.cs:502` | `this.PushCache(guid, new GruntMessageCacheInfo { Status = GruntMessageCacheStatus.NotFound, … }); return guid;` |

**All eight are fail-OPEN.** Not one logs, throws, or rejects.

**Site 8 is the sharpest and the one worth a rule.** `InternalListener.cs:501-503` is the server's **inbound wire-message dispatch**. An unrecognised message type causes it to **cache a `NotFound` status and `return guid` as though the message had been handled.** No exception, no log line, no rejection — the caller receives a normal return. Compare `Packager.cc:786`, where the same situation produces an ERROR-level log.

**Discriminator:** *"unrecognised dispatch key"* is **loud in havoc and silent in Covenant**. Stated honestly, this is a *weak* signal on its own — it is an absence-of-a-log, observable only where you already have full process logging, and absence of a log is confounded by log level, rotation, and collection gaps. **It is filed as corroborating, not primary.**

## 5. GUID formatting — the axis confirmed by enumeration, not inherited

D133 established `ToString("D")` at 46 sites and `ToString("N")` at 0. **Generalised here to every GUID-formatting site.**

**Method:** every `ToString(` with a format argument applied to a Guid-valued expression, plus every `Guid.NewGuid()`, `Guid.Parse`, and `CreateSecureGuid` use.

| fact | value | source |
|---|---|---|
| helper | `Utilities.CreateSecureGuid()` | `Utilities.cs:90` |
| JWT claim use | `new Claim(JwtRegisteredClaimNames.Jti, CreateSecureGuid().ToString())` | `Utilities.cs:44` |
| launcher ProgId | `Utilities.CreateSecureGuid().ToString()` | `Launcher.cs:112` |
| seeded password / username | `CreateSecureGuid().ToString() + "A"` / `CreateSecureGuid().ToString()` | `CovenantService.cs:3955`, `:3958`, `:3993`, `:3996` |
| compact form `"N"` | **0 sites** | — |

**Verdict:** Covenant emits the **36-character hyphenated form** at every site enumerated; the 32-character compact form does not occur. **A framework that never emits the compact form is discriminable on wire shape** — a GUID-shaped field observed in Covenant traffic will carry hyphens.

**Honest limit on this finding:** `Guid.ToString()` with no argument *is* the `"D"` format, so a bare `.ToString()` is indistinguishable from `.ToString("D")` without tracking the default. This was already the D133 caveat and it is not re-resolved here. The claim in this report is the narrower, verifiable one: **`"N"` occurs 0 times**, and no site in scope requests a compact form. **The zero has a proven non-empty operand: the GUID-formatting enumeration returned 6 non-zero sites before the `"N"` count was taken.**

## 6. The co-occurrence rule, built and tested

D133 §2 observed that Covenant's dispatch is **both** enum-typed and string-keyed, with every model enum carrying a parallel switch on its own member-name literals — so **the co-occurrence set is the signature, not any single token.** That assertion is converted here into a rule with a measured false-positive count.

**Individual tokens are insufficient — six collisions found:**

| token | covenant | havoc | metasploit | mythic | pupy | sliver | collisions |
|---|---:|---:|---:|---:|---:|---:|---|
| `Stage0` | 43 | 0 | **18** | 0 | 0 | **31** | 2 |
| `PowershellCommand` | 5 | 0 | **1** | 0 | 0 | **5** | 2 |
| `SetJitter` | 29 | 0 | 0 | 0 | 0 | **5** | 1 |
| `ASPSESSIONID` | 1 | 0 | **1** | 0 | 0 | 0 | 1 |
| `ImplantTemplate` | 494 | 0 | 0 | 0 | 0 | 0 | 0 |
| `SetConnectAttempts` | 29 | 0 | 0 | 0 | 0 | 0 | **0** |

**Comparator: `Select-String -SimpleMatch` per token per tree, extension filter `.cs,.razor,.yaml,.yml,.cpp,.cc,.h,.hpp,.go,.py,.rb,.rs,.js,.json`. INPUT CARDINALITY: 10 tokens × 6 trees = 60 cells.** `Stage0` alone would fire 18 times inside Metasploit and 31 times inside Sliver — that is the whole reason a single-token rule fails.

**THE RULE (per-file conjunction, not per-tree presence):**
> A file is a Covenant-dispatch match iff it contains **all four** of `SetConnectAttempts` **AND** `SetKillDate` **AND** `MessageTransform` **AND** `BridgeMessengerCode`.

**Result — the rule was run over all 6 trees:**

| tree | files matching ALL 4 | 
|---|---:|
| **covenant** | **1** — `covenant\Covenant\Core\CovenantService.cs` |
| havoc | **0** |
| metasploit | **0** |
| mythic | **0** |
| pupy | **0** |
| sliver | **0** |

**False positives against the other five corpus targets: 0 / 5.** The rule fires once in the corpus and only on Covenant.

**Two things this does NOT establish, stated so the number is not overread:**

- **It is a source-tree discriminator, not a wire discriminator.** The 4 tokens are *code* tokens. Their presence in a file is evidence of Covenant source, not of Covenant traffic. **For the wire, use §2's `SetJitter`/`SetConnectAttempts`/`SetKillDate` `EnumMember` values and the `InternalListener.cs:1040-1047` RSA parameter names.**
- **A 0/5 result against 5 in-corpus targets is not a 0 false-positive rate.** The denominator is 5, not the world. Any legitimate .NET application that happens to serialise a `SetConnectAttempts`-named member alongside a `MessageTransform` member would match. **The baseline in §7 is what bounds this.**

## 8. What this report does not establish

- **No wire capture was performed.** Every "wire-observable" verdict is a static inference from `[EnumMember]`/`[JsonProperty]` presence. **No traffic was generated, replayed, or observed**, and no claim is made about on-the-wire byte encoding (JSON vs XML, whitespace, ordering).
- **No execution, no network, no live C2, no REA, no `open_binary`.** All findings are byte-level reads of source text.
- **The 620 vendored `wwwroot` files were excluded, not read.** A fingerprint living in a shipped JS bundle would be missed. Stated as a scope limit, not as an absence.
- **`GruntHTTP.cs` (60,548 B), `GruntSMB.cs` (54,607 B), `GruntBridge.cs` (54,084 B) were not exhaustively read** in this pass. Their frame construction, headers, and length handling are **unexamined here**, and §3's fail-open verdict is explicitly not extended to them.
